# Stage0102: Mac Metal FIFO latency request

On Darwin with an actual Metal adapter, request DesiredMaximumFrameLatency=1. Other backends keep the original default. FIFO, format/alpha/view selection, reconfiguration, frame ownership, callbacks and lifetime locks are unchanged. The pinned Go binding forwards the positive hint; native code defaults omitted hints to2 and clamps requests to backend caps; supported Metal configures maximumDrawableCount=latency+1. Request1 therefore targets two rather than three drawables. This is an unproven native experiment, not a guarantee of latency improvement or acceptance. Fewer drawables can block acquisition; native cadence, latency and close/resize behavior must be checked. Revert the request if native backpressure regresses accepted cadence, cleanup or responsiveness. Existing default/tagged GPU ownership race and vet profiles are the software checks.
