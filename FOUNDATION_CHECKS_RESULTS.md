## Interpretation and controls

The heap measurements are forced-GC, isolated shaper lifetimes, not a complete workbench benchmark. The ~257 MiB live shaper is incompatible with the provisional 40 MiB empty-workbench Go-heap target under this fallback policy; a production font policy/resource strategy must be measured. Zero glyph IDs do not prove typographic, color-emoji or caret correctness. The shaper release control shows most memory is releasable; it does not prove the application's global cache is bounded.

Early font runs could not discover system fonts in the sandbox and produced deceptively low heap with missing glyphs. They are saved as `diagnostic-font-discovery-failed*` and excluded from conclusions. The corrected harness verifies discovery explicitly using an owned writable font-index directory. The standalone toolkit requires `-nogui`; the offscreen build tag alone did not prevent desktop initialization. Two stalled owned diagnostic processes were stopped before rerunning with that flag. The first minimized-idle harness also nested main-thread dispatch around `Minimize`, which dispatches internally; that owned process was stopped, the wrapper corrected, and the failed run retained separately without an idle claim.

Initial lifetime controls without a per-cycle Cocoa autorelease pool grew substantially. Draining pools removes most of that apparent growth. Those unpooled runs are retained as harness diagnostics, not evidence of a confirmed adapter leak. Pooled fresh-window runs still have a small residual trend; native allocator/GPU attribution remains required. A hidden raw GLFW view with no GPU context is a deliberately narrow lifetime fixture.

The package copy is development-only. No certificate, signing account, notarization submission, upstream issue/PR or release publication was used. Meaningful stapler/Gatekeeper results required local execution outside the filesystem sandbox; sandbox-only LaunchServices errors are not treated as distribution results. No input-source, Dictation or VoiceOver setting changed in this run; previous restored-setting evidence remains in the native-input report.

## Regression verification

The reproducible build/vet and focused race checks pass, including the new editor/cluster tests, existing lazy-spelling tests and the four portable bridge/queue packages. An expanded run of the three affected upstream packages does **not** pass: `text/lines.TestMarkup` panics while compiling its lexer tree (`*tree.NodeBase` instead of `*lexer.Rule`). The identical focused test also fails in the unchanged four-patch nativeinput baseline, so this is recorded as a pre-existing failure rather than a new patch regression. The upstream textcore graphical suite stalled under the restricted runtime and its specifically identified process was stopped with a saved diagnostic stack. No complete upstream-suite pass is claimed. Broader lexer/render-test setup remains to be resolved before integration; targeted passing tests do not close that issue.
