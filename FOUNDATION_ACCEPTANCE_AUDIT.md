## Reproduction and next work

Run `prototypes/foundationintegration/run.sh` to prepare owned pinned dependencies, then `check_foundation.sh [output-directory]` on macOS. The audit CLI exits 0/1 for its ordering/buffer assertions, and 2 for harness errors. The runner validates evidence integrity and always exits 1 while this audit's G1 scope remains open. The verifier does not turn a reproduced contract failure into acceptance. Build/source/output hashes and exact commands are recorded in [the manifest](prototypes/foundationintegration/evidence/20261010/manifest.json).

Address the demonstrated ordering seam first: establish an ordering boundary for legacy keys/actions relative to already admitted native snapshots, retaining bounded batches and testing updates admitted on both sides of that boundary. Increasing the batch limit alone would move the failure threshold. Then define visual bidi caret/selection and native range-geometry contracts, global resource budgets, and complete the larger interactive performance workload. Resolve the broad regression discrepancy before proposing the local patches for upstream acceptance. Live IME/VoiceOver validation requires verified input-source selection and screen-reader observations; platform/release gates require their actual environments.

Each changed code area and this report is reviewed separately with Prism; review reports and dispositions are committed under `reviews/`. Prism code review is distinct from runtime foundation acceptance.
