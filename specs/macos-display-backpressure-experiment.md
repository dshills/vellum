# Opt-in macOS display backpressure experiment

This is a prospective experiment. Ordinary rendering keeps its current policy. It does not establish performance improvement, startup readiness or Mac release acceptance.

`desktop.Window.EnableDisplayBackpressure(timeout)` must be called before the native layer's first drawable acquisition. It refuses late installation, unsupported platforms, a repeated installation, missing native resources or a timeout outside 100 ms through 5 s. There is no disable/reset operation that can discard an outstanding frame. The public Vellum option is `cogent.Driver.ExperimentalDisplayBackpressure time.Duration` (zero/off). It wraps the existing NativeAttach hook before native window publication/show and preserves the accessibility/text attachment identity. Both loaded demos provide the explicit `-experimental-display-backpressure=1s` diagnostic flag, requiring perf plus a presentation journal; `Config.DisplayBackpressureNS` declares the exact positive timeout only when enabled.

The Core owner reserves one monotonically identified CPU batch before layout/composition admission, including the early resize-cache replay branch. Another request while that batch awaits presentation becomes one dirty notification. An unchanged batch retires its unused reservation. Async dispatch transfers the reservation through the existing render-context/window owners and CPU batch completion.

Immediately before entering native `nextDrawable`, the layer obtains a separate monotonic acquisition sequence from that batch. Another live acquisition is refused before entering Metal. A nil acquisition retires only its sequence and allows the same CPU batch to retry. Successful drawable ownership retires on its actual presented callback, not on GPU work completion or the return of `Present`. Batch credit is reusable only after both CPU completion and native acknowledgement. An acknowledged acquisition may be followed by another sequence within the same batch without overlapping native ownership.

One actual presented handler forwards independent scalar identities to the existing diagnostic recorder and the display gate. Recorder tags, timestamps, sequence population, skipped/unavailable states and strict validation remain intact. An actual matching callback with finite presented time equal to zero acknowledges a skipped drawable and retires its native sequence without terminal refusal. It is not successful display evidence. Negative or nonfinite times remain malformed and latch experiment failure. Both CPU completion and native acknowledgement are still required before the batch can be reused; a prior deadline failure cannot be reset by zero acknowledgement.

Acknowledged skips do not invent dirty work or unconditionally schedule another composition. Existing blocked dirty admission can request one coalesced mailbox wake at retirement. An unchanged on-demand scene may remain skipped until a real model/layout/visibility change; automatic replay or occlusion recovery is outside this policy. Raw observer delivery and the strict presentation validator remain unchanged: an armed/tagged skipped sample is still not presentation success and cannot qualify latency or cadence.

The gate retains a bounded set of scalar fields, one bounded paint-mailbox notification and one watchdog timer. Duplicate, stale or post-close callback identities cannot retire a newer acquisition. Callback code does not call window/main-thread APIs or retain native objects. Window close revokes authority before native/resource teardown and does not wait for a missing display callback.

A deadline latches `DisplayBackpressureError` while retaining any live native token. Later admission refuses; it never assumes that timeout means presentation or permits another overlapping drawable. Actual late acknowledgement may retire ownership but cannot clear failure. The gate owns a buffer1, receive-only refusal stream independent of FrameTrace. One monitor per native attachment forwards the first typed refusal through the existing Driver.Run failure/close machinery. Attachment close cancels, retires and joins that monitor. The caller must report/refuse and close that diagnostic window. Occlusion may prevent callbacks; this candidate therefore remains opt-in and does not claim a production recovery path or automatic visibility recovery.

`DisplayBackpressureSnapshot` exposes detached issued/retired/epoch/active/native-pending/dirty/CPU-finished/closed/failure state. Retired counts reservations, including no-composition cancellation; it is not a presentation count. This snapshot alone is not a startup fence: queued paints, resize fallback, owner transit and actual first-input admission need a separate reviewed barrier. No startup exclusion, sample population, performance budget or release threshold changes.

Before native execution, reviewed fake asynchronous tests must cover CPU completion before display, callback before CPU end, unavailable retry, stale/duplicate callbacks, overlapping-acquisition refusal, unused batches, finite-zero acknowledgement before/after CPU finish, malformed callbacks, lost callback refusal, close, identity bounds and races. Actual ManualWindow/software-compositor tests must prove deferred changed pixels resume after acknowledgement and that early resize replay cannot bypass admission. The original Core103 source plus the new Core integration tests should compile and fail behaviorally. Stage104 replay must match the complete prospective source vector. Native efficacy and startup readiness remain pending separate review. All source/check execution requires root admission; no test result is implied by this specification.

Stage105 follows104 with exact pins for the finite-zero gate condition, its API comment, actual gate regressions and a controlled real-pixel changed/unchanged ownership test. This specification adds no test-result, native or measurement acceptance claim. The original source-104 ordinary/after-Show failures and exact unrecorded timestamp value remain historical failures.
