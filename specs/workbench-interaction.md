# Workbench interaction and complete session contract

Status: implemented local SDK contract, with acceptance evidence under `docs/reports/workbench-interaction/`.

## Model and state ownership

`workbench.Workspace` and its version 1 single-window `Layout` remain compatible. `workbench.Session` adds version 2 complete multiwindow persistence: each logical window's title, OS-unit position and client size, its split tree/tab order/active tabs, and an explicit focused window/panel with a request serial. Group identities are unique across the entire session. Every registered panel appears exactly once. Empty dock groups collapse; empty windows disappear. The session contains 1–32 windows, at most 256 groups, and at most 32 split levels. Titles and identities are nonempty valid UTF-8 without NUL. Client bounds range from 160×96 to 16384×16384; position coordinates are bounded. Positioned bounds distinguish an intentional origin from automatic OS placement.

The session owns layout only. Documents, selection and undo history belong to application domain state. All Session and WorkbenchGroup access is confined to Application.Do, Drain or View execution. Once attached to a native WorkbenchGroup, its Session and registered Panels remain stable; clients route layout changes through Group.Apply, Load, Float or Close rather than replacing controller fields or mutating the attached Session directly. Portable unattached Sessions remain independently mutable. Snapshots and restored trees are privately cloned. Every failed move, split, activation, resize, restore and decode leaves the prior whole session unchanged.

`Session.Dock` takes a final insertion index after removing the source panel. Float creates a new single-panel window. CloseWindow appends the closing window's panels to a nominated surviving tab group in traversal order. If the focused panel belonged to the closing window, it becomes the active tab in the target and its focus request transfers to the target window. Closing the final session window is application shutdown rather than destruction of its saved layout.

## Native adaptation and topology transactions

`cogent.WorkbenchGroup` registers one private Workbench and native root per logical window, using monotonically unique application lifetime IDs. Panel.View is appropriate for portable nodes. Panels containing native extensions use Panel.NewView(nativeWindowID), a lazy factory producing an independent view closure and native adapter for each window; the closure shares domain objects rather than widget pointers. Compatible keyed content survives moves within a window. Cross-window movement deliberately mounts fresh native resources; the application domain state survives.

Apply validates a private candidate. It opens added native registrations, retires removed registrations, atomically saves the candidate if PersistencePath is configured, then publishes the session and invalidates all survivors. Publication is the commit point; a refused wake after external application cancellation does not report an already committed transaction as failed. An Open, Close or save failure compensates accepted registrations and keeps the previous model. Rollback reopens removed windows with fresh lifetime IDs. If compensation fails, the application closes and the previous domain session is retained; it does not continue with divergent native windows. Transactions and native rendering are serialized on the application owner. Workers may post commands but must not call the group directly. External cancellation terminates the application and does not promise native topology rollback.

WindowCloseExtension.WindowClosed runs under the application owner before native registration cancellation. Record-tree traversal notifies every hook even after a failure and returns the joined errors. Closing a floating window returns panels to the first surviving window/tab group and autosaves; retired adapters ignore duplicate close notifications. Controller-driven removal retires the adapter mapping before requesting closure, so a synchronous close notification cannot reenter the topology transaction; failed close requests restore that mapping. A failed close transfer/persistence is reported and terminates the application rather than losing panels in a running session. The final window captures current native geometry and saves before closing.

## Pointer, menu and focus behavior

Native tab buttons handle SlideStart/Move/Stop. A release over a tab selects its before/after insertion boundary and reorders the source tab. A release in a group's center docks as its final tab; group edges split horizontally or vertically, with a quarter-size edge band capped at 64 render pixels. Releasing inside the source scene without a dock target, including over a splitter or padding, cancels the drag. Releasing outside the source scene bounds floats the panel; a scene without established geometry cannot authorize floating. Normal clicks activate tabs. Splitter changes update the model ratio. Native callbacks capture event data and enqueue PostWindow; they never enter Do recursively. Atomic generations drop callbacks from retired native dock trees. Refused mailbox delivery retains the controlled model, requests native restoration and reports the error on the next owner refresh. Queued transaction failures reach the current Workbench or WorkbenchGroup error handler. Without a handler, failures coalesce into one bounded first-failure report until the next Sync, which returns it to the driver's central failure path before mounting or destroying any dock content. Later queued failures or delivery refusals cannot overwrite that first failure.

Each tab's context menu offers Float and explicit destination window/group entries for cross-window redocking. Menu target snapshots contain model data only; native handlers never acquire another window's render lock or read the shared session. A moved panel's focus request selects and focuses its destination tab; the destination native window is raised once per new focus serial. Ordinary redraws preserve current editor focus.

Cross-window pointer drag is not implemented by this backend: Cogent's slide capture is scoped to the originating native window. The implemented cross-window route is the explicit destination menu. OS drag payload export/import is a separate platform requirement. No physical pointer test is claimed from synthesized events.

## Persistence and geometry

Decode rejects unknown JSON fields, trailing content, cycles/depth, missing or duplicate panels/groups/windows and invalid bounds/focus. Complete session data is capped at 256 KiB. Save writes a same-directory temporary file, fsyncs and closes it, then replaces the destination; failed pre-replacement writes preserve the prior file. The API guarantees atomic file replacement, not directory-fsync durability after power loss. Load validates before publishing or opening windows. Existing native windows restore changed title, size and positioned bounds as well as dock contents. Model bounds are requested only once per changed value; unrelated refreshes preserve native move/resize geometry that is still awaiting owner capture. Native move/resize snapshots coalesce into one bounded latest slot per window and flush through the owner at 100 ms intervals, limiting event-driven persistence to ten writes per second. Transient zero/tiny/oversized native geometry and the Windows minimized position sentinel are ignored; restored session validation remains strict. Delayed captures check the original window lifetime, explicit-restore epoch and latest admission sequence, so retired adapters, closed applications and timer callbacks posted out of order are harmless. Concurrent producers cannot replace a newer pending observation. Native close clears pending captures and flushes current valid geometry directly. Geometry epochs discard native snapshots queued before a later explicit bounds restore; native-originated observations do not advance these epochs, so a burst can retain its final snapshot. Accepted native observations mark their bounds as applied without requesting native writes. Stale geometry cannot undo an explicit restore. Group.Load rebases the persisted focus serial into a new live request and forces a new geometry request even when saved bounds equal the previous model values. Restored window frames are constrained to keep their title bars accessible on current screens; resulting actual geometry is captured on subsequent native events.

The session format does not persist document contents, maximization/minimization/fullscreen state or stable monitor identities. Applications save documents independently and must use domain revision guards for asynchronous analysis.

## Acceptance

Portable race tests verify float/redock/split/reorder/close transactions, global identity checks, complete JSON/file roundtrips, snapshot isolation and rejection immutability. Native adapter race tests verify resource isolation, owner-mailbox gestures, native close transfer, refused/stale delivery and compensation for failed Open, Close and autosave.

`go run ./cmd/docking-smoke` exercises real native windows, shared document state, programmatic cross-window docking and the native close callback. `go run ./cmd/docking-smoke -interactive -timeout 2m` enables physical pointer/tab-menu checks without altering OS preferences. Windows/Linux desktop acceptance is tracked separately from macOS evidence.
