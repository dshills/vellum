# Git-free Mac SDK build and private app package

The owned Mac build tool now works from an extracted Vellum SDK without a Git checkout. Previously its distribution collector unconditionally required Git, so an actual clean SDK build failed before compiler invocation. The collector now accepts a fully checked SDK manifest and payload, keeps declared source provenance separate from observed integrity, and explicitly records that authentication has not been independently verified. The Git SDK producer remains unchanged.

Exact membership, canonical paths, module and native capsule identity, checksums and file identities are checked before collection and sampled again after it. SDK hashing has manifest/member/aggregate/count bounds and refuses files that truncate or grow beyond their admitted size. The six distributed CLI entrypoints suppress helper bytecode writes during ordinary Python execution; undeclared payload members remain rejected. SDK mode refuses include-untracked rather than borrowing an ancestor Git repository's identity.

All 151 affected regression methods pass across eight Python suites. Coverage includes Git fallback boundaries, malformed and changed SDKs, symlinks/special members, path/count/byte limits, final resampling, normal Python CLI invocation, and a deterministic file-growth/short-read control. Internal review caught an EOF-driven read loop in the first version; the original 150-test pass, exact old source and interim review are preserved. The corrected 151-test result applies to the fixed source.

A fresh private SDK made from the disclosed working candidate at base `0372adc` passes normal-Python app generation, real optimized Go 1.25.6 Darwin ARM64/CGO compilation, and before/after inventory plus linker-map receipt checks. The exact source-built WGPU archive has nonempty selected object members. The executable is packaged into an unsigned, unnotarized `.app` carrying an independently checked caller-selected notice bundle. All five owned command groups terminate and are observed absent; no application is launched. The source trees, prepared dependencies, earlier SDKs and the fresh extracted SDK remain unchanged during the run.

The SDK has 8,049 files. Against the preceding clean `0372adc` SDK, only seven Python source/test files differ; Go/C/native/assets are unchanged. Existing 26-default-main plus one tagged-helper build evidence is reused for those unchanged inputs. The new owned native build is a real SDK-tool integration check, not a repeated all-demo run. This report and specification edits were added after the tested precommit SDK was produced; neither the archive nor its declared dirty source is represented as the eventual clean commit.

The [evidence record](evidence.json) binds raw local logs, receipts, source inputs, archive, executable, linker map, app notices and retained failures. The app notice bundle carries 176 components and 393 original declaration files, including the native archive's 82-component compiled superset. Its applicability remains review-required and distribution audit pending. This is neither exact surviving-code notice closure nor rights approval.

Native application acceptance, measured 60 Hz presentation/input qualification, physical/human checks, resource/endurance gates, remaining asset/declaration applicability and owner distribution approval remain open. No signing, notarization, installation, public publication or OS-setting changes occurred.
