# Identity outline preflight

Retained static TrueType outlines now carry four control-point extrema. Exact
identity-transform GPU scene preflight checks the two corners with the same
float32 arithmetic instead of revisiting every used point. Font/GID and exact
segment backing guard the summary under the existing cache mutex. Nonidentity,
foreign/unretained/evicted outlines and invalid summaries use the old point loop.
Cold successfully retained outlines can use the freshly computed summary.

Logical retrieval, segment and extent-product charges remain unchanged. Metadata
is bounded by the existing 1,024-entry limit and excluded from the 2 MiB segment
capacity limit. CPU rendering, mask/scanner output, packet emission and scene
admission limits retain their contracts; GPU scene rendering remains opt-in.

An independent original-traversal oracle compares accepted bounds and integer
extents for actual glyphs across seven scales, coordinate boundaries and seeded
random positions. Focused race tests, complete renderer race tests and headless
native compute parity pass. The microbenchmark for one cached composite glyph
checks median 624.4 ns with traversal versus 15.00 ns with cached extrema, both
0 B and 0 allocations. This local operation does not establish a frame-rate gain.

The candidate was tested through a Go overlay without editing prepared native
sources. Its four bytestring hashes are bound to the source review, binaries and
comparison. Formal adoption uses owned patch 0053, with original/output hashes,
and ordinary preparation. The final prepared source must exactly match that
reviewed overlay, with all other prepared source hashes unchanged.

A preflight found 17 PNG outputs generated by full renderer tests. They are
retained outside the prepared tree; every baseline source hash remained exact.
The original receipts and refused comparison preflight are retained. The corrected
preflight allows only those exact generated output hashes in old receipts and
requires a clean original prepared tree for all measured processes.

## Matched native comparison

40 ordinary native processes run five alternating pairs for each fixed/variable
10,000/1,000,000-row case, with 128 guarded warmup callbacks and 120 samples per
process: 4,800 samples total. All paired geometry and callback guards pass.
The original and candidate use the same frame observer and opt-in GPU scene mode.

| Case | Original p95 / p99 (ms) | Candidate p95 / p99 (ms) |
| --- | --- | --- |
| fixed-10000 | 8.373 / 10.129 | 6.702 / 7.306 |
| fixed-1000000 | 7.908 / 8.345 | 6.529 / 6.885 |
| variable-10000 | 8.403 / 9.201 | 6.844 / 7.791 |
| variable-1000000 | 8.056 / 8.433 | 6.670 / 6.937 |

Pooled p95 improves by 17.2–20.0%; mean UI work improves by 20.1–22.1%.
Median process allocation changes are within 0.2%; this is a measured host UI-work reduction,
not demonstrated allocation reduction. Both binaries still fail the unchanged
4 ms p95 / 6 ms p99 targets. These frame metrics exclude queue wait and drawable
acquisition and do not measure GPU completion/presentation. The default CPU
renderer was not included in this matched campaign. All observations are retained.


Preparation regression tests now expect the complete 1–53 patch sequence; all
11 preparation tests pass. Final focused renderer race and adapter vet pass.
The first full adapter race run failed only because the sandbox refused the
existing workbench Unix socket fixture; that receipt is retained separately.
The authorized socket-enabled rerun is the selected full adapter check.
