# Visual bidi navigation and native range geometry

10 October 2026. Implemented for the experimental macOS native TextField, including wrapped text. G1 remains open; broad workbench expansion is still on hold.

The field now draws go-text's wrapped runs in their declared visual order and navigates horizontal arrows through strong paragraph-direction carets at extended grapheme boundaries. Logical selection anchors and editing offsets remain runes. Wrapped boundaries retain a physical line affinity, so reversing arrow movement returns to the same stop. Cross-line arrows follow paragraph direction; pointer placement chooses the physical line before horizontal proximity. Vertical movement and pointer placement refresh layout when queued edits precede rendering. Horizontal scrolling keeps the whole paragraph shaped and clamps its offset when text shrinks.

Geometry uses typographic advance rather than glyph ink. Spaces have cells; combining and emoji ZWJ sequences stay whole. Ligature advance is divided equally at grapheme boundaries. Font GDEF ligature-caret positions are not used. A grapheme split across fallback-font runs is merged before choosing caret edges. Raster selection and composition underlines use these cells, including disjoint bidi fragments. The rasterizer coalesces adjacent selected cells, normalizes ranges for indexed lookup and skips fully clipped fragments. Grapheme boundaries are computed once per interaction layout and shared across runs and raster selection. Render items reuse the immutable layout geometry across repaints. Unsupported vertical/math lines retain legacy pointer and arrow navigation; horizontal scroll extent includes their rendered bounds and advances. No horizontal cells are fabricated for these runs.

The Cocoa adapter receives owned UTF-16 cells, strong carets, viewport and focus-line affinity with the corresponding text and acknowledgement. Invalid or stale publications preserve accepted state. Accepted native edits invalidate old geometry until matching layout is published; refused edits preserve it. `firstRectForCharacterRange:actualRange:` returns the first visible contiguous logical fragment, expands interior-grapheme requests, stops at wraps or disjoint bidi fragments and excludes wholly clipped cells from actualRange. Zero-length queries return insertion geometry. `characterIndexForPoint:` converts screen points into the view and returns the containing grapheme; blank or clipped areas report NSNotFound. These queries access native copies on the Cocoa owner thread.

The implementation is patch 0011 against the pinned Cogent/go-text experiment; preparation verifies its inputs and reapplies all eleven toolkit patches. [ADR 0010](../decisions/0010-visual-bidi-native-range-geometry.md) records the policy. Its strong-caret and first-fragment contracts are informed by [Pango's visual cursor API](https://docs.gtk.org/Pango/method.Layout.move_cursor_visually.html) and [Apple's NSTextInputClient range API](https://developer.apple.com/documentation/appkit/nstextinputclient/firstrect%28forcharacterrange%3Aactualrange%3A%29?language=objc). This does not establish full UAX #9 conformance or equivalence to a native reference editor.

## Validation

Evidence is in [20261010-visual-text](../../prototypes/foundationintegration/evidence/20261010-visual-text).

- Laid-out field arrows for `abc אבג xyz` follow rune positions **1, 2, 3, 4, 6, 5, 7**. Tests also cover RTL paragraph direction, digits, reverse movement, wrapped-line affinity, logical selection/deletion, combining marks, emoji, spaces and synthetic ligatures, and combining graphemes split across clusters or styled runs.
- Edit-before-render vertical movement and pointer placement, plus scrolling after text shrinks, have regression tests. Mixed supported/unsupported arrow transitions and overflowing math advances also have fallback regression tests.
- Actual raster images were inspected with visible Hebrew glyphs, selection, wrapping and clipping. The explicit system-font cache avoids a sandbox-denied default cache initialization in the offscreen fixture.
- The native fixture queries 15 rendered graphemes. Its expected screen rectangles and points derive independently from physical rendered cells, native view bounds and actual framebuffer dimensions; they are compared to Cocoa's results with a 0.05-point tolerance.
- Hidden Cocoa queries cover surrogate-interior requests, multiline and bidi fragments, insertion stops, outside requests, focus-line affinity, clipping, scale/translation, invalid/stale publications and accepted/refused native edits.
- Go vet, transport/input/semantics race tests, focused interaction tests and the full offscreen core package pass. 1,000 native window lifetimes attach/detach once each and drain 11,000 accepted updates. The existing native protocol/saturation fixture still acknowledges 13 edits with no application rejection or outstanding credit at shutdown.
- A 12,000-rune many-run interaction microbenchmark takes approximately 4–5 ms per layout in the recorded three-iteration run. It is a local sample, not a whole-app memory or latency budget. The selected 8,000-rune raster replay benchmark takes about 2.1 ms with reused geometry and coalesced fills, versus about 4.8 ms before coalescing; both are local samples.

Prism reviewed implementation and audit changes. Findings drove fixes to clipped actualRange, stale vertical/pointer layout, repeated grapheme scans, scroll clamping and independent native rectangle validation. Further review added visible-cell availability assertions, masked-layout freshness checks, pointer-line priority and preservation of legacy fills for unsupported vertical/math runs, RTL wrap transitions and mixed-axis/aggregate-line bounds. Final fallback review addressed stale scroll on layout refresh, repeated geometry construction during redraws, unsupported-line pointer/arrow fallback and unsupported scroll extents and vertical movement through mixed unsupported lines. Audit schema 2 now checks visual bidi independently and requires native geometry evidence; schema 1 historical evidence remains readable. Final reports and dispositions are saved under `docs/reviews/visual-text-20261010/`.

## Acceptance boundary

This closes the demonstrated TextField logical-arrow and insertion-only geometry defects for the tested macOS path. The multiline code editor still has its separate fixed-grid navigation/positioning and no native composition/range adapter. Vertical text, math interaction, native-reference comparisons, full live Japanese/Chinese candidate-panel and VoiceOver workflows, Windows/Linux runtimes, global resource budgets, full performance workloads, clean-machine trusted release and upstream extension acceptance remain open. Earlier broad text-suite discrepancies remain recorded in the acceptance audit.
